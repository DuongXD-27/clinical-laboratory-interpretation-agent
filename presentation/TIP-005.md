# 2. TIP-005 GOAL

Deliver the **Hybrid Assistant user experience** on the existing patient-facing application.

Required capabilities:

```text
AI Assistant launcher
Expanded chatbot panel
Contextual Assistant
Mandatory onboarding
Session-aware conversation
Suggested Action rendering
OCR review integration
Guest behavior
Patient behavior
Safe backend/frontend integration
```

The frontend is a presentation and interaction layer.

It MUST NOT reconstruct medical logic.

```text
       │

                    │
                 click
                    │
                    ▼
```

Do not replace existing patient navigation.

# 4. AI ASSISTANT LAUNCHER

Implement a clearly identifiable assistant launcher.

Preferred behavior:

```text
Desktop:
floating/sticky assistant icon near a lower screen edge
→ click
→ assistant drawer/panel opens

Mobile:
assistant launcher remains reachable
→ click
→ responsive chat surface / bottom sheet / near-full-width panel
```

Follow existing frontend design patterns.

Do not introduce a new UI framework.

The icon must not obstruct important:

```text
buttons
forms
medical values
navigation
alerts
OCR confirmation controls
```

Use an existing icon library already in the frontend if available.

Do NOT add an icon dependency solely for this feature.

If none exists, use a simple local SVG/component consistent with project conventions.

# 7. MANDATORY ONBOARDING

```text

```

```text

     ↓

     ↓

```


and provide the approved acknowledgement flow.

Do not bypass onboarding by manipulating local component state.

# 13. CONTEXTUAL ASSISTANT

The Assistant should expose context-aware suggestions where server-approved context permits.

Examples:

After supported analysis:

```text
Giải thích kết quả này
Xem xu hướng

```

On history context:

```text
Xem báo cáo
Xem xu hướng
```

On OCR review:

```text
Xác nhận OCR
```

The frontend must consume structured SuggestedAction objects.

Do not infer action from natural-language message text.

---

# 14. EXPANDED CHAT

The opened Assistant panel supports natural-language interaction.

Flow:

```text
user message
    ↓
Orchestrator API
    ↓
typed OrchestratorResponse
    ↓
render message
    ↓
render structured payload
    ↓
render server-approved SuggestedActions
```

Do not make direct low-level medical service calls based on parsed user text.

All free-form chat goes through the approved Orchestrator entrypoint.

# 16. NO PROSE PARSING

```javascript
if (message.includes("xem xu hướng")) {
  navigate(...)
}
```

```javascript

```

```text
response.suggested_actions
```

only.

---

# 17. ACTION SECURITY

SuggestedAction renderer must reject/ignore invalid action payloads.

Never execute:

```text
javascript:
arbitrary URL
raw route string from LLM
patient_id
user_id
authorization override
unknown payload
```

Navigation mapping must be locally allowlisted by action enum.

Example concept:

```text
VIEW_HISTORY
→ known frontend history destination

VIEW_TREND
→ known frontend trend destination

CONFIRM_OCR
→ known existing OCR confirmation flow
```

No arbitrary external navigation.

```text

```
